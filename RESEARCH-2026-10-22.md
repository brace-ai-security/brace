# BRACE evidence re-review — 2026-10-22

**Framework version: 2.0.1.** All 53 recommendations and their verification recipes were re-read: B01–B12, R01–R14, A01–A07, C01–C08 and E01–E12. The sections below retain the evidence, per-item assessments, issue-specific affected/fixed versions, and retrieval limits. Review date is not publication date. “Retain” supports the control principle; it does not establish a deployed pass or release approval.

This review updates references and records proposed technical refinements. It does not silently adopt those refinements, reproduce exploits, audit installed dependencies, or requalify the review models. The separately approved release-policy clarification is implemented: **high-stakes or high-autonomy reviews report evidence, gaps and unknowns, without a BRACE GO/NO-GO verdict.** Any deployment decision belongs to accountable people and requires a gradual, closely monitored rollout with bounded exposure, explicit stop conditions, tested recovery and review before expansion. Even a report with no identified gaps is not evidence of no vulnerabilities.

## Implications to discuss

1. **Configured remediation:** several MCP patches require explicit issuer/audience/complexity settings, stored-credential cleanup or server lifecycle changes. A version bump alone can leave the vulnerability exposed.
2. **Future execution:** hooks, skills, plugin commands, decoders and object loaders belong in the execution inventory. Changing trusted instructions or hooks can be consequential even when the current operation is only a file write.
3. **Persistence and isolation:** test files, summaries and handoffs alongside memory APIs; exercise namespace delimiter collisions, batch/async operations and effective authorization after hooks.
4. **Before the model runs:** schema resolution, image/audio decoding and token counting can trigger SSRF, code execution or shared-engine resource exhaustion before prompt safeguards act.
5. **Evidence and recovery:** signatures do not make deserialization safe; full action evidence does not require putting raw secrets in ordinary logs; cooperative cancellation is not proof of termination.
6. **Risk and authority:** the exact BRACE gates, six identity fields and decision-time context metric remain BRACE judgments. High-risk findings support a human rollout decision; they do not settle it.

#### Newly published since the last 2026-10-16 targeted review

- **vLLM untrusted image-format dispatch — published 2026-10-20.** [GHSA-h3rc-j82p-2c3h](https://github.com/vllm-project/vllm/security/advisories/GHSA-h3rc-j82p-2c3h) lists affected **0.30.0**, patched **0.32.0**. Maintainer report reproduces loader-level execution; the HTTP path was source-traced, not exercised end to end. **Implication:** treat decoder and preprocessing executables as part of B01/B11/C01; restrict actual decoded formats, patch decoders and test boundaries under R01/R03. Not a new Ghostscript flaw; not evidence every vLLM host has RCE.
- **vLLM legal-length audio can crash a shared engine — published 2026-10-20.** [GHSA-8397-8qf6-f2gm](https://github.com/vllm-project/vllm/security/advisories/GHSA-8397-8qf6-f2gm) lists affected **0.31.0**, patched **0.32.0**. Phi-4 multimodal eager attention retains matrices across encoder layers; a request within default audio limits can exhaust GPU memory. **Implication:** B07/R01 need media/decoder/accelerator resource limits rather than just token/cost limits.
- **vLLM token boundary causes CUDA-context failure — published 2026-10-20.** [GHSA-q97c-p368-75c4](https://github.com/vllm-project/vllm/security/advisories/GHSA-q97c-p368-75c4) lists affected **≤0.30.0**, patched **0.32.0**. A pre-tokenized prompt with an out-of-range token can pass validation and kill the engine for some model vocabularies/tensor-parallel settings. **Implication:** validate semantic ranges as well as JSON types, include primitive inference interfaces in R01/C06.
- **vLLM permissive CORS/default no-auth combination — published 2026-10-20.** [GHSA-vvpg-rrww-wpmh](https://github.com/vllm-project/vllm/security/advisories/GHSA-vvpg-rrww-wpmh) labels affected **“All versions (default config)”**, patched **0.32.0**. Wildcard allowed origins plus no configured API key lets another website call a browser-reachable local/internal server and read responses. This is not a claim that CORS bypasses a secret bearer token. **Implication:** authenticated inference endpoints, explicit origins when browser access is intended, and browser-to-private-network tests under B08/R01.

### Discussion priorities

1. Expand “execution surface” to include hooks, skills, plugin commands, decoder/preprocessing binaries and model/config loaders. This connects existing controls rather than requiring a new top-level checklist item.
2. Treat changing the agent’s future trusted behavior as a high-impact action, with reviewed instruction/config provenance and runtime self-modification denial tests.
3. Make single-request media/GPU exhaustion and semantic token-range tests concrete under existing budgets/validation controls.
4. Make verification-tool/loader patch maintenance explicit, and clarify that signatures and clean scans answer different, limited questions.
5. Keep recovery images and models subject to current security/lifecycle policy, while preserving revoked permissions and state integrity.

### Findings for discussion

The 21 recommendations remain useful. New evidence mostly sharpens test coverage and qualifies assurances; it does not establish that completing a checklist guarantees security. Important changes to consider before altering requirements:

1. Persistent influence includes ordinary files, handoff artifacts, and generated summaries, even with the memory tool disabled. R05/R06 currently discuss memory explicitly; discuss making all later-consumed persistent agent output part of this boundary.
2. Test namespace encodings, batch calls, async paths, and authorization-hook transformations, rather than only clean tenant A/B labels. October 21 and September 28 LangGraph advisories show isolation can fail below an apparently correct application policy.
3. Recovery must avoid unsafe deserialization as well as verify integrity. Authentic but dangerous checkpoint object construction is a distinct question from a changed checksum.
4. Run graph evidence should minimize sensitive content. Keep action identity, authorization outcome, policy/approval IDs and safe argument summaries by default; retain necessary prompt/argument detail in restricted evidence. “Full audit” should not suggest logging every raw payload.
5. **S34 is more conservative than BRACE release gates.** The coauthor-hosted [Careful adoption PDF](https://www.ncsc.govt.nz/assets/guidance/Documents/Careful-adoption-of-agentic-AI-services_FINAL.pdf), introduction p4, recommends agentic AI use for low-risk, non-sensitive tasks. BRACE's possible GO for high-stakes systems after stricter gates is its own risk policy, not an agency-endorsed conclusion. No new date is claimed for this already-cited document. CISA's landing page returned HTTP 403; the NCSC-NZ PDF was read.
