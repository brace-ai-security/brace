# GitHub implementation advice audit

Selected outputs: `R01.json`, `R01.advice.json`, `R02.json`, `R02.advice.json`. No corrections or superseded selections. Both reports are source-only observations, without a deployment/release verdict. Exact served auditor identity is unknown. No complete vulnerability key or recall denominator is available.

R01 provides the stronger boundary and preservation analysis. Its raw stdio logging finding and conditional delete-state actor/replay concern are supported; current target, repository ID, expiry, form/protocol and GitHub authority checks must survive any redesign. R02 correctly identifies the OAuth callback login denial: both an unauthenticated error and a mismatched state complete the flow. State must be checked before the error branch while preserving genuine provider errors and cancellation. [Pinned callback](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/internal/oauth/callback.go#L83-L132).

The most consequential false assurance is R02's universal claim that authorization URLs avoid model context. Supported legacy and MRTR fallback paths return `UserAction.Message` as ordinary tool text, and PKCE constructs that message with the URL. Removing this path would remove supported client compatibility and must be an explicit trade-off, not an assumed compatible fix. [Pinned tool-result fallbacks](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/internal/ghmcp/oauth.go#L154-L205), [PKCE manual fallback](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/internal/oauth/flow.go#L133-L153).

No concrete recommendation was classified regressive or an established high-impact advice error. R01's config-only metadata expectation is conditional deployment hardening: replacing intentionally request-derived/proxy-derived modes globally needs a migration decision. R02's constant-time comparison is minor hardening; its Docker publishing advice already matches README/docs. Its container-detection failure claim exceeds supplied runtime evidence because headless random-port login can fall back to device flow. [Pinned fallback](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/internal/oauth/flow.go#L115-L128).

R01 incorrectly excludes subprocess lifecycle: the OAuth browser launcher starts xdg-open/open/rundll32 and reaps it asynchronously. Its exhaustive issue-assessment permission inventory also omits `models: read`; this is a minor inventory error, not extra repository write permission. R02's roughly 500-file inventory is inaccurate for this packet (298 files under pkg/github, including tests/snapshots); it does not create a handler coverage denominator. [Pinned launcher](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/internal/oauth/env.go#L23-L47), [workflow permissions](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/.github/workflows/ai-issue-assessment.yml#L10-L13).

R02's body-buffering concern is explicitly conditional, so it is not an asserted missing-limit error. The supplied router already places the 5 MiB limit before both readers and passes the same limit to the SDK. [Pinned order](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/pkg/http/handler.go#L138-L159).

Primary-source completeness remains limited: R01's narrow advisory-index observation is correct, but neither report compares all supplied Go SDK/server maintainer records. Those records predate this commit and do not establish present exposure. The declared SDK 1.8.0 is above supplied historical Go SDK affected ranges; the historical completion nil-dereference report has an explicit nil guard in current source. No upgrade or present-vulnerability assertion follows from historical “latest main” text. [Pinned completion guard](https://github.com/github/github-mcp-server/blob/f38526264abb14961b32cea386e38ec6d3cf674f/pkg/github/server.go#L203-L206); primary records: `research/sources.json` GHSA-w4q6-qw23-4rg7 and Go SDK advisory collection.

Bounded follow-up lead: bearer host scoping compares host/port but not scheme. A controlled same-host HTTPS-to-HTTP redirect test would establish whether token confidentiality needs additional scheme enforcement; no attacker-controlled redirect or deployment exposure is proven here.
