B05
Destructive-action interception		Blocker
Gap		The agent can book and pay for a ticket with no person checking first.
How to fix
  1. Open src/tools/flights.py and find book_flight (line 14).
  2. Before the booking call, show the traveler the flight, the price and the card.
  3. Only book after the traveler clicks to confirm.
  4. Save who confirmed, when, and the price they saw.
  5. Add a test that books with no confirmation. The booking must be refused.

Done when: No ticket is bought unless a person confirmed that exact flight and price.

E08
Bounded delegated authority		Blocker
Gap		The itinerary writer is meant to write text only, but it is given every tool, including booking and paying for flights.
How to fix
  1. Open src/itinerary_writer.py and go to line 10.
  2. Pass an empty tool list to the writer instead of registry.all_tools().
  3. Add a test that runs the writer and checks that it has zero tools.
  4. Run the writer once and check the log shows no tool calls.

Done when: The itinerary writer cannot call any tool, and the new test passes.

B03
Credential lifetime and handling		Required
Gap		If the token is missing, the code uses a saved default token for the travel-docs server.
How to fix
  1. Open src/mcp_client.py and go to line 9.
  2. Remove the default value so the code stops when no token is set.
  3. Ask the platform team to cancel the default token on the server.
  4. Load the token from the secret store, and make it expire within a day.

Done when: No token is written in the code, and the old default token no longer works.

B09
Egress allowlist		Required
Gap		Each booking sends the traveler's name and email to a marketing service. Nobody listed this service, and nothing blocks it.
How to fix
  1. Ask the privacy team if this data may go to the analytics service at all.
  2. If not, delete the call in src/tools/flights.py on line 17.
  3. If yes, send an ID instead of the name and email, and list the service under connections.
  4. Set the network so the agent can reach only the services that are listed.

Done when: The agent can only reach listed services, and no name or email goes to analytics.

book_flight, marketing analytics (adtrack)Infrastructure
R03
Prevent output and log leakage		Required
Gap		Itineraries are emailed as HTML written by the model, so a hidden link or image could leak data.
How to fix
  1. Open src/tools/notify.py and go to line 8.
  2. Send the body as plain text, not HTML.
  3. Only send to the email address in the traveler's profile.
  4. Add a test that tries to send to a different address. It must be refused.

Done when: Emails are plain text and only go to the traveler's own address.

send_itinerary, email delivery APIAgent team
R02
Separate data from instructions and test injection containment		Required
Needs proof		Advisory text from an outside website reaches the model, but no test shows an attack in that text is stopped.
How to fix
  1. Write ten fake advisories that tell the agent to book a flight or send an email.
  2. Feed each one to the agent in a test setup, not in production.
  3. Repeat each one five times and count how often the agent obeys.
  4. Save the results with the date and the code version.

Done when: A dated test record shows none of the fake advisories led to a booking or an email.

R08
Security monitoring		Detection
Gap		Nobody is told if the agent suddenly books many flights or spends much more than usual.
How to fix
  1. Log every booking with the run, the traveler and the price.
  2. Set an alert when one run books more than two flights.
  3. Set an alert when daily spend is twice the normal amount.
  4. Test both alerts once and save the result.

Done when: Both alerts fire in a test and reach the on-call person.
