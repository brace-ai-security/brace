MCP security: specifications, deployment practice, and research

MCP sources checked 2026-10-16. Protocol requirements, optional extensions, industry profiles, deployment reports and experimental defenses have different authority. No resource listing certifies a gateway or deployment. Benchmark results depend on their models, versions and attacker assumptions; no combined production attack rate is claimed.

Protocol and authorization specifications

MCP authorization, 2026-07-28

Protocol requirements for protected HTTP access: discovery, resource indicators, issuer validation and audience-bound access tokens. Authorization is optional in MCP itself; BRACE requires it for protected tools.

EcosystemSpecification

MCP Streamable HTTP, 2026-07-28

Transport requirements, Origin validation, and matching request metadata headers to the body. Check the negotiated version before applying legacy session rules.

EcosystemSpecification

MCP security best practices

Official guidance on confused deputies, token passthrough, SSRF, local process risks and scope minimization. A separate backend needs its own authorized credentials.

EcosystemOfficial guidance

RFC 9700: OAuth security best current practice

OAuth security baseline for grants, redirect handling, token protection and deployment threat models.

EcosystemIETF BCP

RFC 8693: OAuth token exchange

Standardized exchange where supported. Distinguishes original subject, current actor and prior actor history; prior nested actors grant no extra authority.

EcosystemIETF RFC
